**Known API facts (checked against the npm package `rabbit-ear@0.9.41`, GPLv3):**

| Area | What exists |
|---|---|
| Sheet constructors | `square(scale?)`, `rectangle(width?, height?)` |
| Fold operations | `graph.simpleFoldLine(graph, line, { assignment, foldAngle, vertices_coordsFolded }, epsilon)`, `graph.flatFold(graph, line, assignment, epsilon)`, `graph.reverseFold(graph, line, vertices_coordsFolded, epsilon)`, `graph.simpleSquashFold(graph, foldedEdge, flatEdge, vertices_coordsFolded, epsilon)` |
| Folding a subset of faces | `graph.foldGraph`, `graph.foldGraphIntoSubgraph` |
| Layers | `layer(graph, epsilon)` returns a solver with `.faceOrders()`, `.count()` and `.compile()`; there is also `layer3D` |
| Folded coordinates | `makeVerticesCoordsFolded(graph, rootFaces)`, `makeFacesWinding(graph)` |
| Ready-made bases | `blintz`, `waterbomb`, `kite`, `fish`, `bird`, `frog`, `windmill`, `squareFish` |
| No petal-fold primitive | It must be built from other operations |

Line objects use the shape `{ vector: [x, y], origin: [x, y] }`. The exact namespace paths (for example `ear.graph.simpleFoldLine` vs `ear.simpleFoldLine`) are confirmed in Plan 1, Task 2.
