# Phase 5: Curved and Wet Folding (XPBD) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A soft-paper mode built on an XPBD sheet solver. It gives curved creases, wet-folding sculpting and gentle physical handling, while exact FOLD frames stay the source of truth for flat states.

**Architecture:**
- `src/soft/` holds a remesher (FOLD frame → particle and triangle mesh, refined along creases), a CPU XPBD reference solver (the test oracle), a WebGPU solver with identical constraints, and a hand-off module that converts between rigid and soft states.
- Sculpted steps are stored in the history as mesh snapshots.

**Tech Stack:** As before, plus WebGPU (WGSL compute) and three.js's `WebGPURenderer` for soft mode only.

**Spec:** `docs/superpowers/specs/2026-10-20-08-curved-wet-folding-design.md`

## Global Constraints
- Performance target: **60 fps at about 5,000 particles** on a mid-range GPU. It degrades by reducing iterations first, then by using a coarser mesh.
- Self-collision is visual only. Regions with **more than about 10 stacked layers** fall back to rigid rendering.
- Without WebGPU, soft mode is hidden (with a tooltip explaining why); the rest of the app is unaffected.
- Leaving soft mode snaps back to an exact frame if the shape is still flat-foldable; otherwise it becomes a "sculpted" step.
- No Co-Authored-By trailers.

**Settle before Task 3 (decided with the user):** the open questions in spec 08 — the UX for drawing curved creases, how a wet fold "dries", and whether sculpted steps are allowed in lessons. Raise them with the user before starting Task 3.

## Review Focus
1. **The tab is backgrounded mid-simulation (rAF paused).** On return there's no huge time step and no explosion; the step is clamped to 1/30 s. Covered by a test in Task 2.
2. **A dense crease region on a low-end GPU.** The quality governor reduces iterations before the frame rate drops below 30. Covered by a test in Task 4.
3. **A share link or `.fold` export containing sculpted steps.** It includes a mesh snapshot, or warns when the snapshot is over 1 MB. Covered by a test in Task 5.
4. **Undo across the soft/rigid boundary.** It restores the exact rigid frame. Covered by a test in Task 5.
5. **WebGPU device loss.** Fall back to the CPU solver at reduced resolution, without losing the model. Covered by a test in Task 3.

### Task 1: Remesher
**Files:** create `src/soft/remesh.ts`; tests alongside.
**Interfaces:**
- Produces: `remesh(frame: Frame, poses: FacePose[], targetEdge: number): SoftMesh`, where `SoftMesh = { positions: Float32Array; tris: Uint32Array; creaseHinges: { a; b; c; d; restAngle; stiffness }[]; boundary: Uint32Array }`.

- [ ] **Step 1: Write the failing tests.**
  - The total triangle area equals the paper area.
  - Every crease edge is represented by mesh edges (no crease crosses a triangle).
  - The hinge rest angles equal the frame's `edges_foldAngle`.
- [ ] **Step 2:** Run the tests. Expected: FAIL.
- [ ] **Step 3:** Implement. Refine along creases, then run a constrained Delaunay triangulation on each face.
- [ ] **Step 4:** Run the tests. Expected: PASS.
- [ ] **Step 5:** Commit with `feat(soft): crease-aware remesher`.

### Task 2: CPU XPBD reference solver
**Files:** create `src/soft/xpbd.ts`; tests alongside.
**Interfaces:**
- Produces: `class SoftSolver` with:
  - `constructor(mesh: SoftMesh, params: { bendCompliance; creaseCompliance; iterations; wet: boolean })`
  - `step(dt: number)` (dt is clamped to 1/30)
  - `pin(i, p)`, `unpin(i)`
  - `positions(): Float32Array`

- [ ] **Step 1: Write the failing tests.**
  - 10,000 steps on a hanging sheet with no explosion (max |v| stays bounded).
  - `step(5)` behaves like `step(1/30)`.
  - With crease constraints only, a flat model stays flat to within 1e-4.
  - Wet mode lowers the bending stiffness: a pinned sheet sags more.
- [ ] **Step 2:** Run the tests. Expected: FAIL.
- [ ] **Step 3:** Implement the distance, bending (dihedral), crease-hinge and pin constraints, solved with graph-coloured Gauss–Seidel.
- [ ] **Step 4:** Run the tests. Expected: PASS.
- [ ] **Step 5:** Commit with `feat(soft): CPU XPBD reference solver`.

### Task 3: WebGPU solver and self-collision
**Files:** create `src/soft/gpu/*.wgsl`, `src/soft/gpu/GpuSolver.ts` and `src/soft/collision.ts`; tests alongside (run headed Chromium with WebGPU in Playwright).
**Interfaces:**
- Produces: `GpuSolver`, with the same API as `SoftSolver`, plus `createSolver(mesh, params): SoftSolver | GpuSolver` (picks the GPU when it's available and falls back on device loss).

- [ ] **Step 1: Write the failing tests.**
  - The GPU and CPU solvers' positions agree within 1e-3 after 200 steps on a reference mesh.
  - Self-collision stops a flap from passing through a single sheet.
  - A simulated device loss switches to the CPU solver and keeps the positions.
- [ ] **Step 2:** Run the tests. Expected: FAIL.
- [ ] **Step 3:** Implement, using spatial hashing for collisions and skipping regions with more than 10 stacked layers.
- [ ] **Step 4:** Run the tests. Expected: PASS.
